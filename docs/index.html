Persistent, structured memory for AI coding agents — built on markdown, backed by git, open to every agent.

The problem

CLAUDE.md / RULES.md

Manual context files go stale, hit token limits, and no agent reliably updates them.

Vector RAG

Optimises for proximity, not causality. A goal and its dependent task may have low cosine similarity but a critical dependency relationship.

Proprietary memory

Mem0, MemGPT, LangMem — locked to one vendor. Not accessible to other agents. Not human-readable or git-versionable.

No standard

Claude Code, Cursor, GPT agents each have their own memory. They contradict each other. There is no shared memory layer.

How Mastishk works

.mastishk/
  intent/         # goals and constraints — rarely changes
  state/          # tasks, progress, blockers — append-only
  knowledge/      # decisions, stack, architecture — grows over time
  issues/         # errors and blockers — never deleted
  memory-map.json # DAG linking all nodes

Every memory node is a .msk.md file — markdown with YAML frontmatter. Human-readable, git-versionable, no database. When an agent needs context, inject traverses the dependency graph from matched nodes. Causality, not cosine similarity.

Six protocol claims

  • 1. Layered memory Three semantic layers — intent, state, knowledge — with different persistence, update rules, and agent trust levels.

    State writes are append-only. Knowledge writes replace. Intent requires human confirmation.

  • 2. DAG traversal Context injection traverses a dependency graph from task-matched seed nodes at depth 2.

    If Task A depends on Goal B constrained by C, all three are returned — because they are causally connected, not just semantically similar.

  • 3. Filesystem-native nodes Every memory node is a .msk.md file with YAML frontmatter and a markdown body.

    No database. No binary format. No vendor dependency. Git-diffable, human-editable.

  • 4. Git as episodic memory mastishk checkpoint commits the memory folder. The git log IS the agent's cognitive history.

    Cryptographically verifiable. Branchable. Rollback to any prior memory state.

  • 5. Confidence-weighted Referee Every node carries a confidence score (0.0–1.0). The Referee blocks writes that contradict existing nodes.

    Silent overwrites are impossible. Conflicts create an issue node for human resolution.

  • 6. Ambient capture Post-commit hooks and agent MCP calls keep memory current without manual effort.

    Memory degrades gracefully rather than going catastrophically stale.

One command to connect any agent

mastishk instruct --agent <name> writes the right config file, then prints a memory summary so your agent is ready immediately.

# Claude Code — updates CLAUDE.md with full memory workflow
mastishk instruct --agent claude-code

# Cursor — writes .cursor/mcp.json
mastishk instruct --agent cursor

# Windsurf — writes .windsurf/mcp.json
mastishk instruct --agent windsurf

# Any custom agent — inject output to stdout for piping
mastishk instruct --agent api

MCP — manual config

Or add one block directly to your MCP config. The agent gains five memory tools automatically.

// .cursor/mcp.json · .windsurf/mcp.json · claude_desktop_config.json
{
  "mcpServers": {
    "mastishk": {
      "command": "npx",
      "args": ["@mastishk/mcp", "--memory-dir", ".mastishk"]
    }
  }
}

Tools available: mastishk_inject, mastishk_update, mastishk_log, mastishk_status, mastishk_checkpoint.

Packages

@mastishk/core

Schema (Zod), read/write, graph, DAG traversal, inject. The protocol's TypeScript foundation.


npm install @mastishk/core
@mastishk/cli

The mastishk command. init, inject, update, log, scan, status, checkpoint, instruct, hook.


npm install -g @mastishk/cli
@mastishk/mcp

MCP server for Claude, Cursor, and Windsurf. Five tools, zero config beyond the path.


npm install -g @mastishk/mcp
